# Система оперативного розыска ГИБДД

Учебный проект: сотрудник ГИБДД ведёт список разыскиваемых автомобилей и получает оповещение, когда камера «видит» один из них. Реальных камер нет — их имитирует отдельный **сервис камер**.

## Состав проекта

| Папка | Что это |
|---|---|
| [backend](backend/README.md) | Сервис ГИБДД: REST API и WebSocket на FastAPI, база MySQL, приём событий от камер, оповещения |
| [camera-service](camera-service/README.md) | Сервис камер: имитатор на чистом Python, отправляет события обнаружения в backend |
| [AvtoDozor](AvtoDozor/README.md) | Мобильное приложение сотрудника (React Native / Expo) |

## Как это работает

1. Сотрудник входит в приложение по логину и паролю, сервер выдаёт JWT-токен.
2. Приложение открывает WebSocket и получает оповещения в реальном времени.
3. Список розыска передаётся сервису камер.
4. Раз в заданный интервал сервис камер выбирает случайный автомобиль из розыска и случайную камеру и отправляет событие в backend.
5. Backend сохраняет оповещение и доставляет его сотруднику (в приложение и при необходимости на почту).
6. Сотрудник реагирует: «Принято» → «Автомобиль задержан?» (Да / Нет).

Оповещение можно создать и вручную через сервис камер (удобно для демонстрации).

Нужны **Python 3.12**, **MySQL** и (для мобильного приложения) **Node.js** + Android Studio / телефон.
